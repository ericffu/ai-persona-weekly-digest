# 角色详细规则

四个角色各自的目标、素材取舍、语言改写规则、额外标注维度与输出模板。生成哪个角色就读哪一节,不用整份读完。

每个角色的示例都基于真实历史条目(Kimi K3 / Claude for Teachers 等)改写,演示"改写到什么程度"。

---

## AI 小白

**目标**:看得懂、有代入感。读完知道"这周 AI 又出了啥、跟我有什么关系",不是来学技术的。

**素材取舍**:

- 保留:能直接体验到的产品/功能(App、插件、能下载的东西)、破圈的社会性话题(监管新规、"AI 有没有意识"这类)
- 砍掉:论文板块几乎全砍(除非有个真的好玩的人话结论)、大部分开源项目(除非普通人能直接用)、Twitter 技术圈内部争论
- 条数:8–10 条,宁少勿滥,不硬凑

**语言与结构改写**:

- 去参数化——"2.8 万亿参数 MoE、100 万 token 上下文"这种要翻译成"它有多能干、多贵、我用不用得起"的感受性描述,能用类比就用类比
- 结构从"发布方/日期/要点/为什么关注/来源"改成口语三段式:**是什么 → 能拿来干嘛 → 为什么值得你知道**
- 不用"MoE""benchmark""上下文窗口"这类术语,出现了就用大白话代替,不是加注解

**输出模板**:

```markdown
# AI 周报 · 小白版 · <START> — <END>

> 这周 AI 圈发生的事,挑对普通人有意义的部分,说人话讲清楚。

## 这周最值得知道的 3 件事

- 一句话 x3,口语化,不用术语

## 详情

### 1. <口语化标题,不是官方产品名直译>
- **是什么**:一两句话
- **能拿来干嘛**:普通人视角的用法/影响
- **为什么值得你知道**:一句话
- 来源:[<站点名>](<url>)

### 2. …
```

**HTML 分节映射**:"这周最值得知道的 3 件事"→ `.highlights`;"详情"整节 → 1 个 `section.category`(`id="detail"`),TOC 只需 1 个锚点。

**改写示例**(素材:Kimi K3 发布):

> ### 1. 一个国产免费开源模型,一下子追到了顶级付费模型的水平
> - **是什么**:月之暗面出的新模型 Kimi K3,是目前公开的开源模型里规模最大的一批,还能看懂图片、一次能读几十万字的文档
> - **能拿来干嘛**:如果你自己有够强的电脑/服务器,理论上能白嫖一个顶级水平的 AI;普通用户等它接入 App 后就能直接用
> - **为什么值得你知道**:开源模型第一次追到了贵模型的水平,以后用 AI 可能不用非得给大厂交钱
> - 来源:[Kimi 官方](https://www.kimi.com/blog/kimi-k3)

## 产品经理

**目标**:别人的产品怎么设计的、市场怎么打的,有什么可以借鉴的思路。

**素材取舍**:

- 强化:AI 产品/工具/Agent 板块(产品定位、目标用户、定价策略、增长数据)、行业动态里的商业模式创新
- 弱化到只剩"能力水位"一句话:技术参数细节
- 基本砍掉:论文板块(除非直接影响产品体验的新交互范式,例如影响 Agent 记忆设计的研究)

**结构改写**:不按公司罗列,按**主题聚类**重组——交互范式 / 商业模式 / 增长打法 / 值得关注的新玩家,这更接近产品经理平时做竞品分析的方式

**额外标注维度**:每条必须有一句"值得借鉴的设计点"——这是这个角色版本的核心增量,不是可选项

**输出模板**:

```markdown
# AI 周报 · 产品经理版 · <START> — <END>

> 这周值得产品人关注的设计思路、商业打法与增长动作,按主题而非公司组织。

## 本周 3 个产品叙事
- 提炼主题,不是复述新闻,例如"通用 Agent 开始抢编程工具的地盘"

## 一、交互范式 / 产品设计
### 1. <产品> — <一句话定位>
- 设计亮点:…
- **值得借鉴的点**:…
- 来源:[<title>](<url>)

## 二、商业模式 / 增长打法
### 1. …

## 三、值得关注的新玩家/竞品动态
### 1. …
```

**HTML 分节映射**:三个二级标题 → 3 个 `section.category`,建议 `id` 用 `#interaction` `#business` `#newplayers`,TOC 对应 3 个锚点。

**改写示例**(素材:百度秒哒 3.5):

> ### 1. 百度秒哒 3.5 — 从"生成应用"到"交付产品"的闭环
> - 设计亮点:新增 SEO Agent、一句话生成 Skill、多应用共享后端,把"生成 → 交付 → 运营"三段打通成一条链路
> - **值得借鉴的点**:无代码工具的护城河不在"能不能生成",而在生成之后能不能持续运营——秒哒把运营能力(SEO、多环境、资源分级)也做成了产品功能,这是从"工具"到"平台"的关键一步
> - 来源:[新浪财经](https://finance.sina.com.cn/tech/2026-07-19/doc-iniiifmi3590759.shtml)

## 技术研发

**目标**:值得深挖的技术细节、能不能自己上手复现或部署。

**素材取舍**:

- 强化:模型发布(架构、benchmark、定价、部署门槛)、论文(技术贡献本身)、开源项目(依赖、能不能跑起来)
- 弱化到几乎不提:融资、政策(除非直接影响技术选型,比如出口管制导致某模型限制使用)

**语言风格**:可以保留、甚至加深术语,不用为可读性妥协准确性;链接优先级——论文/GitHub/官方技术博客 > 媒体报道

**额外标注维度**:

- **部署门槛**:显存需求、卡数、量化方案(如果素材里没提到就写"未披露",不要编)
- **技术差异点**:和上一代或对标竞品比,架构/训练方法上的关键不同

**输出模板**:

```markdown
# AI 周报 · 技术研发版 · <START> — <END>

## 一、模型:架构与部署门槛
### 1. <模型名>
- 架构 / 参数:…
- Benchmark:…
- **部署门槛**:…
- **技术差异点**:…
- 来源:[论文/技术博客](<url>) · [GitHub](<url>)

## 二、论文:核心技术贡献
### 1. <标题>
- 核心贡献:…
- 来源:[arXiv](<url>)

## 三、开源:能不能跑起来
### 1. <org/repo>
- 依赖 / 环境要求:…
- 一句话:解决了什么工程问题
- 来源:[GitHub](<url>)
```

**HTML 分节映射**:三个二级标题(模型/论文/开源)→ 3 个 `section.category`,可以直接沿用通用版的锚点习惯 `#models` `#papers` `#opensource`。

**改写示例**(素材:LongStraw 论文):

> ### 1. LongStraw — 固定 GPU 预算下的百万 token RL 后训练
> - 核心贡献:面向长上下文 RL(GRPO)的架构感知执行栈,8 张 H20 上完成 Qwen3.6-27B 210 万 token 的分组打分与反向传播
> - **部署门槛**:组规模从 2 增到 8 仅多 0.21GB 峰值显存,压力测试可达 446 万 token,单机多卡可复现
> - **技术差异点**:把"训练上下文远短于推理上下文"这个常见瓶颈往前推了一截,不依赖超大集群
> - 来源:[arXiv PDF](https://arxiv.org/pdf/2607.14952) · [GitHub](https://github.com/MindLab-Research/longstraw)

## XX 行业从业者(参数化)

**目标**:不只是看行业对应板块,而是用一个"行业透镜"重新扫一遍全部素材,挑出"看似不相关但其实会影响这个行业"的条目;再叠加一轮专项搜索补足行业深度。

**前置要求**:必须先问清楚具体行业(不能自己猜),可选追问关注的具体公司/机构名单——不局限于竞品,合作方、监管对象、上下游任何想跟踪动态的公司都算。

**素材来源两路**:

1. **专项搜索结果**(见 SKILL.md「行业专项搜索」)→ 进入"直接相关"小节
2. **通用素材池里的跨界条目** → 通用 7 类里任何一条,只要"对该行业有外溢影响"就挑出来,不管它原本挂在哪个板块。判断标准举例(以教育行业为例):
   - 通用 Agent 产品(非教育定位)是否可能降维打击某个细分教育功能
   - 监管/政策动态是否影响该行业产品的合规设计
   - 融资动态里出现的同行业公司
   - 底层模型降价/开源是否降低了自建该行业垂直能力的成本门槛

**额外标注维度**:每条"直接相关"和"跨板块外溢"条目都要补一句**"对我们业务的启示"**——这是这个角色版本真正的增量价值,不是简单摘抄或翻译。

**输出模板**:

```markdown
# AI 周报 · <行业> 从业者版 · <START> — <END>

> 本期行业:<行业>。以该行业视角重新审视本周 AI 动态——既聚焦行业专属 AI 进展,也把通用板块中影响该行业的内容单独挑出来解读。

## 本周对<行业>最重要的 3 件事
- 一句话 x3

## 一、<行业>AI 动态(行业专属)
保留原行业专项的结构,呈现该行业特有的 AI 应用、工具、政策和模式创新。
### 1. <标题>
- 要点:…
- **对我们业务的启示**:…
- 来源:[<title>](<url>)

## 二、模型发布 / 新版本
通用板块结构,按该行业视角筛选和解读。
### 1. <标题>
- 要点:…
- **对<行业>的潜在影响**:…
- 来源:[<title>](<url>)

## 三、AI 产品 / Agent
同上。

## 四、行业动态(融资、收购、监管)
同上。

## 五、开源项目
同上。

## 六、深度观点
同上。

## 七、关注公司动态(仅当用户给了公司名单时出现,否则整节约略)
### 1. <公司名> 本周动态
- 来源:[<title>](<url>)
```

**说明**:通用板块(模型发布、AI 产品、行业动态、开源、深度观点等)不必全部出现——通用素材池里该行业视角下值得挑出来的条目够多就单独成节,条目少或该板块与行业关联度低可以合并或省略。核心原则是**保持和通用周报类似的板块结构感**,不要把所有通用内容合并在一个"跨板块外溢"的大锅里。

**HTML 分节映射**:
- 第一个 `section.category` 固定为行业专项(`#industry`)
- 后面的通用板块按实际出现的数量映射,每个板块对应一个 `section.category`,ID 按内容定(`#models` `#products` `#funding` `#opensource` `#opinion` 等)
- 「关注公司动态」只在用户给了名单时才出现第 N 个 `section.category`(`#companies`)
- TOC 锚点列表跟着实际分节数量走,一个板块一个锚点

**改写示例**(行业=教育,素材:Claude for Teachers,来自「行业专项」;素材:Kimi K3 发布,来自「模型发布」):

> ### 1. Claude for Teachers — Anthropic 免费面向全美 K-12 教师
> - 要点:免费开放高级 Claude 能力 + 教学技能库,接入 50 州学术标准,可按学生分层生成教案;认证教师账号默认关闭训练,符合 FERPA
> - **对我们业务的启示**:"通用基座 + 行业标准 RAG 注入"是巨头教育产品化的共同打法,和我们"垂直数据反哺模型"的路线是两种不同赌注,值得对比评估投入优先级
> - 来源:[Anthropic 官方](https://www.anthropic.com/news/claude-for-teachers)

> ### 1. Cursor "Sand" [源自:AI 产品]
> - 要点:Cursor 内部代号 Sand 的通用办公 Agent,面向邮件、表格等日常事务,是其首个瞄准非开发者的产品
> - **对<行业>的潜在影响**:如果通用办公 Agent 把"批量整理/初筛"这类事务能力做成基础设施,教研/教务的部分事务性工作可能被外部通用工具而非教育垂直产品接管,是否要提前布局差异化能力值得讨论
> - 来源:[Tech Times](https://www.techtimes.com/articles/320271/20260713/cursors-sand-agent-eyes-claude-cowork-market-before-spacex-rewrites-its-roadmap.htm)
